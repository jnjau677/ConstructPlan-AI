## 2025-03-09 - Client-Side API Inputs and Error Sanitization in ArcSystem
**Vulnerability:** Input prompts of unlimited length could allow payload size and denial-of-service issues, while raw backend exception exposure risked leaking sensitive runtime variables and the API credentials of Gemini AI (`GEMINI_API_KEY`) to the browser console.
**Learning:** Client-side Vite configuration textual substitution (`process.env.*`) is visible dynamically or in minified code if evaluated raw. Furthermore, when exceptions occur during downstream LLM API requests, raw console logging outputs the complete exception context, which often includes parts of the API keys/auth headers or internal infrastructure layouts.
**Prevention:** Always restrict inputs to a strict maximum length (e.g., 4000 characters) at both the UI layer (utilizing `maxLength` attributes and conditional triggers) and the API handler layer. Additionally, actively scrub sensitive process variables (such as `GEMINI_API_KEY`) from error messages using a generic redaction utility before printing them to standard logs, and output generic, friendly error states to end-users instead of raw system stack traces.
