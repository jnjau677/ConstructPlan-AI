## 2026-07-19 - Client-Side API Key Exposure via Vite Define configuration
**Vulnerability:** The application was exposing the sensitive `GEMINI_API_KEY` by defining it in Vite's `define` configuration (`vite.config.ts`), which baked the secret directly into the frontend static production assets, leaking it to any user inspecting the client-side JavaScript.
**Learning:** Hardcoding or baking server-side API keys and secrets into client-side code breaks the boundary of trust, exposing critical credentials to attackers. Moving LLM logic and system instructions to a backend serverless function (`api/chat.ts`) and proxying requests securely keeps credentials on the server and protects the AI's integrity.
**Prevention:** Always use server-side proxies, backend handlers, or secure middleware to interface with sensitive third-party APIs. Never reference server-side environment variables directly in client-side code, and avoid using bundler compile-time replacement tools (like Vite `define` or Webpack DefinePlugin) for sensitive keys.
