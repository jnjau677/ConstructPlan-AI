## 2025-03-03 - Client-side Error Sanitization and Safe Env Access in Vite Bundling
**Vulnerability:** Hardcoded API key leakage through console logs, unhandled ReferenceError in environments without `process`, and Client-side Denial of Service via oversized prompt payloads.
**Learning:** Since the application calls client-side services (like `@google/genai`) directly from the browser, any raw error object thrown by the third-party client contains the evaluated API key or internal API endpoints. Because Vite textually substitutes `process.env.GEMINI_API_KEY` at build time, any unhandled error logging would output the raw API key directly to the user's browser console. Furthermore, dynamic checks on `process` would trigger reference errors.
**Prevention:** Wrap all `process.env` references inside try-catch block safeguards. Always implement a specialized, robust error scrubbing helper (`sanitizeError`) to replace API keys and regex patterns with `[REDACTED_API_KEY]` before logging to `console.error` or throwing errors. Implement dual UI-and-service-level input length validation to prevent client-side resource exhaustion.
