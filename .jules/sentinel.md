## 2025-03-01 - Gemini API Input Bounds and Log Sanitization
**Vulnerability:** External API error logging in `geminiService.ts` printed raw Error objects to the client-side developer console, which could leak sensitive information like system instructions, request payloads, or the Gemini API key. Additionally, the system had no validation or enforcement of character limits on user prompts at either the UI or service level, risking massive payload sizes and potential DoS or injection-style abuses.
**Learning:** External API client libraries can append request metadata (such as authentication headers, API keys, and sensitive prompts) to the error objects they throw. Logging these raw objects directly to browser consoles exposes secrets and internals to users. Furthermore, client-side inputs must always have robust bounds enforced both visually and programmatically to ensure secure client-to-service communication.
**Prevention:** Enforce input constraints at both the UI layer (using HTML5 inputs like `maxLength` and React state truncations) and the service layer (explicit character validation checks). Sanitize all console logs by extracting only the clean error message, and explicitly redacting API key patterns (e.g., Google/Gemini `AIza` keys) using regular expressions before logging.
