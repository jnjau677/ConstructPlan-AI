## 2026-08-04 - Enforcing Input Boundaries and Sanitized Error Logging in Gemini API Service
**Vulnerability:** Raw error objects containing stack traces, private model configurations, or potential API boundaries were being logged directly to `console.error` and thrown to the UI, leading to information disclosure. Additionally, lack of input validation could allow oversized payloads to bypass frontend limitations and cause DoS or payload-size errors at the API gateway level.
**Learning:** In public browser-facing single-page applications (SPAs), error handling must explicitly filter backend and model-provider errors before they reach console streams or frontend UI states. Standardizing error sanitization at the service layer prevents sensitive telemetry data exposure.
**Prevention:** Always wrap model-provider requests in try-catch structures that log generic/safe messages to console/log aggregates and throw generic, sanitized errors to the application component context. Enforce strict character and structure validation at both the UI layer (using `maxLength`) and service boundary.
