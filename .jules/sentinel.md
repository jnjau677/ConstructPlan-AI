## 2026-03-05 - Client-Side API Key Log Leakage and Input Exhaustion
**Vulnerability:** The client-side application utilizes an API key embedded into the bundle at build time. Errors thrown by the Google GenAI library could potentially log raw API keys/secrets or other configuration details to the browser console. Additionally, lack of input bounds checks on both the client-side text-areas and the GenAI service level exposed the app to payload size inflation or DoS risks.
**Learning:** Hardcoded/process-defined secrets on the client side must be handled with utmost care. Without strict error sanitization, standard framework error objects might print sensitive parameters (such as raw secrets) to the browser console. Enforcing dual-layer input constraints (in-UI maxLength and service-level bounds checking) prevents DoS/API misuse.
**Prevention:** Always run sanitization helpers in service catch blocks to redact API keys or secrets before logging error strings. Ensure all text inputs have explicit browser-enforced attributes (maxLength) in addition to backend/service-level verification to fail securely and early.
